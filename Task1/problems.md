Анализ проблемных мест:
|#|Проблема|Бизнес-сценарий|
|--|----|----| 
|1|DWH на SQL Server 2008 не масштабируется, отчёты строятся часами|Управленческие решения задерживаются на дни|
|2|Вся бизнес-логика внутри DWH + PowerBuilder|Time-to-market новой фичи|
|3|Медицинские и финансовые данные в одной системе|Риск учетек данных + Риск штрафов от регуляторов|
|4|BI-система кастомизирована поверх DWH, каждый отчёт пишется вручную|Аналитики тратят 80% времени на ETL|
|5|Нет чётких доменов: финтех и клиники тянут данные из одного DWH|Конфликты блокировок, деградация производительности всех сценариев|
|6|PowerBuilder интерфейс для операторов|Ошибки при видении записей пациентов|

Приоритезация проблем и связь с целями бизнеса. Матрицу Эйзенхауэра + MoSCoW:

||Срочно|Не срочно|
|--|----|----| 
|Важно|Проблема №3 (риск утечки мед/фин данных): штрафы, лицензия; |Проблема №4 (BI неэффективен): низкая продуктивность аналитиков;|
||Проблема №1 (отчёты долго готовятся): блокирует управление|Проблема №2 (медленный time-to-market)|
|Не важно|Проблема №6 (PowerBuilder) — влияет, но можно временно терпеть| Проблема №5- решается при переходе на Data Mesh|
