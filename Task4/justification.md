# Выбор ресурсов и IaC-подхода

## Почему выбраны такие VM и диски

| Сервис | Тип VM | Диск | Обоснование |
|--------|--------|------|-------------|
| Kafka | 4 vCPU / 8 GB RAM | 100 GB SSD | Kafka требует быстрых дисков (SSD) для Commit Log. 4 vCPU достаточно для 100+ MB/s throughput. |
| ClickHouse | 8 vCPU / 32 GB RAM | 100 GB SSD (OS) + 1 TB HDD (data) | ClickHouse эффективно использует CPU и память. HDD для исторических данных (дешёво), SSD для hot-данных. |
| Data Portal | 2 vCPU / 4 GB RAM | 50 GB SSD | Легковесный Go-сервис + nginx. Этого достаточно для 1000 RPS. |

## NAT и маршрутизация
- Использован `shared_egress_gateway` вместо отдельной VM-шлюза (дешевле и управляется облаком).
- VM портала получает публичный IP (nat = true), остальные — только приватные.

## Почему IaC (Terraform)?
- **Воспроизводимость**: dev/staging/prod идентичны.
- **Масштабирование**: меняем count=3 на 5 в main.tf → получаем 5 нод Kafka.
- **Прозрачность**: вся инфраструктура описана в Git, нет "ручного шаманства".
- **Безопасность**: секреты (токен) — через переменные, не в коде.

## Как тестировалось?
1. `terraform init`
2. `terraform plan`
3. `terraform apply`
4. Проверка, что все VM созданы, сети работа.
