Домены:

|Домен|Ответственность|Почему независим|
|--|--|--|
|Клиники|Записи, расписание, персонал, инвентаризация, без медкарт и диагнозов|Изменения в записи пациентов не должны влиять на финтех или ИИ. Это ядро операционной деятельности.|
|Финтех и Банк|Счета, кредиты, транзакции, платёжные шлюзы, фин. отчётность|Строгая регуляторика (ЦБ), свои SLA, циклы релизов. Отчётность нужна ежемоментно, независимо от клиник.|
|ИИ-сервисы|Медицинские модели (диагностика, рекомендации), их обучение, метрики качества|Работает с сырыми медданными в изолированном контуре. Результаты (без ПДн) отдаёт другим доменам.|
|Аналитика и Витрины|Сбор агрегированных данных из всех доменов, портал самообслуживания, BI|Единая точка для отчётов без доступа к медданным. Позволяет новым партнёрам быстро получать метрики.|
|Интеграционная шина|Kafka, CDC, API Gateway — общая инфраструктура|Сквозной домен для потоков, но без бизнес-логики|


Аргументация разделения на домены:
|Проблема старой архитектуры|Решение через домен|
|--|--|
|Любое изменение в отчётности требует правки ETL в DWH |Каждый домен сам отвечает за свою витрину. Аналитика просто читает готовое.|
|Медицинские данные мешали финансовым и наоборот|Разные домены = разные БД, разные SLA, разные команды безопасности|
|Новый партнёр (фарма) = месяцы интеграции|Партнёр подключается через стандартные API за 1-2 недели|

Преимущества для бизнеса:
|Преимущество|Измеряется|
|--|--|
|Ускорение вывода продуктов|Time-to-market новых фич|
|Снижение зависимости от DWH|Уменьшение количество инцидентов из-за общих данных|
|Независимое развитие направлений|Клиники и ИИ могут менять свои БД без согласования|
|Масштабируемость|Новый бизнес (например, страховка) добавляется как новый домен|
|Соответствие регуляторам|Медицинские данные никогда не попадают в аналитику|
